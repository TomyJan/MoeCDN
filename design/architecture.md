# 技术选型与部署约束

## 正式应用方向

采用 React、TypeScript、Vite、Tailwind CSS 与 shadcn/ui 作为正式实现方向。shadcn/ui 用于可维护的组件源码和交互基础，外观以本次灰阶设计为准，不直接沿用默认主题。文件图标使用 Material Icon Theme，操作图标使用 Lucide。

本次提交固化需求和原生 HTML 原型，不包含正式 React 项目、构建索引器或 EO Makers 部署配置。开发时需验证具体依赖版本和平台行为。

## 静态构建

Git 推送触发构建：读取资源、生成目录索引和搜索数据、计算文件哈希，再发布静态产物。页面运行不依赖 PHP 或在线目录 API。

索引应包含相对路径、父目录、文件/目录类型、字节数、修改时间、SHA-256/384/512 的 hex 与 Base64。修改时间应采用稳定、可解释的来源；不将 checkout 时间或文件系统创建时间冒充资源创建时间。

原型的 `data.js` 为固定快照，不会随着目录内容变化自动更新；生产索引应在每次构建中更新。原型从浏览器读取媒体元数据，生产版可按性能需要在构建期补充。

## 路由与静态文件

必须同时满足目录路径展示列表和显式文件路径返回原文件。尤其目录已有 `index.html` 时，不能通过覆盖原文件来生成目录页面。

正式部署需验证 EO Makers 的精确路径重写与静态文件优先规则，选择不冲突的页面产物存放位置并将目录 URL 映射到页面。不要只配置统一 SPA fallback 就声称问题已解决；需覆盖目录默认文档、直达、刷新、中文路径、404、下载及现存 `index.html`。

原型的 Python 服务仅用于演示该路由契约：目录返回设计页面，文件返回原始字节，未知路径返回 404。它不代表 EO Makers 已完成配置。

## 性能与安全

列表通过近底部自动追加减少初始 DOM。正式版按数据量评估索引分片、搜索执行位置、缓存和必要的虚拟化，避免首屏加载全部大文件正文。

HTML 预览在无脚本权限的 sandbox 中渲染；Markdown 清理后渲染。哈希按原始字节计算。SRI 跨域使用仍要求资源响应提供正确的 CORS 许可。
